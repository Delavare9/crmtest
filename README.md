# Объекты и задачи — мини-CRM

Учёт объектов (стройки, офисы, склады) и задач по ним. Постановщик создаёт задачу и назначает исполнителя, исполнитель берёт её в работу и сдаёт на проверку, постановщик принимает работу или возвращает с комментарием. Каждое действие попадает в журнал.

Главное свойство системы: **все правила доступа держит база данных**, а не интерфейс. Запрещённый переход статуса, чтение чужой задачи и подделка истории не проходят даже при прямом запросе к API Supabase в обход приложения. Это проверяют автотесты: 87 проверок внутри базы, 23 атаки через REST, 20 тестов логики интерфейса и сквозной сценарий в браузере.

## Что умеет

| Роль | Может |
|---|---|
| Постановщик | Видит все объекты и задачи (включая архив). Создаёт и правит объекты, создаёт задачи, правит их в статусах «Новая» и «На доработке», принимает работу или возвращает с обязательным комментарием, переносит задачи и объекты в архив. |
| Исполнитель | Видит только свои задачи и объекты, где они есть. Берёт задачу в работу и сдаёт на проверку. Больше ничего: не создаёт, не правит, не принимает сам, не удаляет, не видит чужое. |

Жизненный цикл задачи: **Новая → В работе → На проверке → Принята**, с возвратом **На проверке → На доработке → В работе**.

## Стек

| Слой | Что | Версия |
|---|---|---|
| База и вход | Supabase (PostgreSQL 17, Auth, PostgREST) | CLI 3.0.0 |
| Тесты базы | pgTAP через `supabase test db` | 1.3.3 |
| Фронтенд | React, TypeScript, Vite, React Router | 19.3 / 7.0 / 8.3 / 8.5 |
| Интерфейс | Mantine | 9.7 |
| Данные | supabase-js, TanStack Query | 2.119 / 5.106 |
| Тесты API и логики | Vitest | 5.1 |
| Сквозной тест | Playwright | 1.64 |
| Деплой | Vercel (фронтенд), Supabase Cloud (база) | — |

Идентификаторы всех своих таблиц — UUID v7 (по времени создания). Supabase пока работает на PostgreSQL 17, где встроенной `uuidv7()` нет, поэтому используется своя функция; при переходе на PostgreSQL 18 миграция сама переключится на встроенную. Подробно — в [docs/DECISIONS.md](docs/DECISIONS.md).

## Быстрый старт (локально)

Нужны Node.js 22.22+ и Docker.

```bash
npm install
npm run db:start      # локальный Supabase в Docker, миграции применяются сами
npm run env:local     # .env.local с адресом, ключами и паролем демо-пользователей
npm run seed          # пользователи, объекты, задачи во всех статусах
npm run dev           # http://127.0.0.1:5173
```

Демо-пользователи (пароль печатает `npm run env:local`, он же в `.env.local` → `SEED_PASSWORD`):

| Email | Роль |
|---|---|
| manager@example.com | Постановщик |
| executor1@example.com | Исполнитель |
| executor2@example.com | Исполнитель |

## Команды

| Команда | Что делает |
|---|---|
| `npm run dev` | Фронтенд в режиме разработки |
| `npm run build` | Проверка типов и сборка в `dist/` |
| `npm run typecheck` | Только проверка типов |
| `npm test` | Юнит-тесты логики интерфейса (без базы) |
| `npm run db:start` / `db:stop` | Запуск и остановка локального Supabase |
| `npm run db:reset` | Пересоздать локальную базу из миграций (данные стираются) |
| `npm run db:test` | Тесты прав и правил внутри базы (pgTAP) |
| `npm run db:advisors` | Встроенный аудит безопасности и производительности Supabase |
| `npm run db:types` | Перегенерировать типы TypeScript из схемы |
| `npm run db:push` | Применить новые миграции к облачному проекту |
| `npm run seed` | Заполнить базу демо-данными |
| `npm run test:api` | Атаки через REST на запущенный Supabase |
| `npm run test:e2e` | Сквозной сценарий в браузере (один раз: `npx playwright install chromium`) |
| `npm run env:local` | Создать `.env.local` из запущенного локального стека |
| `npm run check` | Всё сразу: типы, юнит-тесты, pgTAP, атаки, сквозной сценарий |

## Структура

```
supabase/
  config.toml            регистрация закрыта, лишние сервисы выключены
  migrations/            uuid_v7 → schema → helpers → triggers → rpc → rls_grants
  tests/                 pgTAP: чтение, запись, переходы, история, UUID v7
scripts/
  seed.ts                демо-данные через настоящие входы пользователей
  local-env.ts           .env.local из локального стека
  env.ts                 общие настройки скриптов и тестов
tests/api/attacks.test.ts   атаки через REST
tests/e2e/                  сквозной сценарий в браузере
src/
  lib/                   клиент, запросы, логика кнопок, подписи, ошибки
  components/            каркас, формы, таблица задач, история
  pages/                 вход, объекты, объект, задача, мои задачи
docs/                    документация системы (ниже)
```
