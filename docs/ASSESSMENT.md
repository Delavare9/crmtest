## Ограничения текущей версии

- **Роль можно сменить только SQL.** Если исполнителя с активными задачами переделать в постановщика, его задачи останутся без исполнителя по роли. Нужна проверка в триггере на `profiles` или процедура передачи задач.
- **Архив односторонний.** Ошибочно заархивированную задачу вернёт только администратор.
- **Нет постраничной загрузки.** Списки грузятся целиком. До нескольких тысяч задач на объект это незаметно, дальше нужна пагинация.
- **Перечитывание всех запросов после действия.** Просто и надёжно на малых объёмах, на больших — лишний трафик.
- **Одинаковый пароль у демо-пользователей.** Удобно для показа, для реальных пользователей — приглашения по почте.
- **Бандл 857 КБ** (251 КБ gzip) без разделения по страницам.

## Что нужно для стабилизации

В порядке важности:

1. **Облачный деплой и проверка в облаке.** Создать проект Supabase и Vercel, `db push`, `seed`, прогнать `test:api` и `test:e2e` против облака. Около 30 минут при наличии доступов.
2. **Защита от смены роли с активными задачами.** Триггер на `profiles`: запрет сменить роль исполнителя, пока у него есть незавершённые задачи. Одна миграция и 2–3 теста.
3. **Секреты CI для облака.** Отдельный job, который по кнопке прогоняет атаки против облачного проекта (секреты в GitHub Actions, не в репозитории).
4. **Ограничение частоты входа.** Проверить и при необходимости ужесточить лимиты Auth в облаке (по умолчанию включены).
5. **Мониторинг ошибок фронтенда.** Подключить сбор ошибок (например, Sentry) — сейчас ошибки видны только в консоли пользователя.
6. **Резервные копии.** Бесплатный тариф хранит копии ограниченно; для рабочего использования — платный тариф с восстановлением на момент времени или регулярный `db dump`.
7. **ESLint.** Подключить, когда `typescript-eslint` поддержит TypeScript 7.
8. **Разделение бандла.** Ленивая загрузка страниц (`React.lazy`) — минус половина начальной загрузки.

## Возможные расширения

Каждое расширение ложится в существующую схему без переделки защиты.

| Расширение | Что меняется | Объём |
|---|---|---|
| Статус «Отменена» | Значение в `task_status`, строки в `task_transitions`, подпись в `labels.ts`. Кнопки появятся сами | Миграция + 3–4 теста |
| Комментарии без смены статуса | Таблица `task_comments` (только добавление), RLS как у истории, событие в журнале | Миграция, экран, 5–6 тестов |
| Восстановление из архива | Функция `restore_task` / `restore_object`, событие `restored` | Миграция + 3 теста |
| Новое поле задачи (срок, приоритет) | Колонка, право на колонку, строка в `tasks_log_update` для «было и стало» | Миграция + 2 теста |
| Вложения (фото работ) | Supabase Storage, политики доступа к файлам по тем же правилам, что задачи | Средний |
| Уведомления исполнителю | Триггер → очередь (`pgmq`) или Database Webhook → письмо/Telegram | Средний |
| Несколько постановщиков с разными объектами | Таблица «постановщик — объект», политики по ней вместо «видит всё» | Средний, затрагивает RLS |
| Отчёты (сроки, возвраты на доработку) | Представления поверх `task_history`, доступ только постановщику | Малый–средний |
| Живое обновление экранов | Включить Realtime для `tasks` и `task_history`: события фильтруются той же RLS | Малый |
| Приглашения вместо паролей | `auth.admin.inviteUserByEmail` + настройка почты (SMTP) | Малый |

## Риски

| Риск | Вероятность | Что делать |
|---|---|---|
| Supabase меняет поведение ключей или CLI | Средняя (CLI 3.x недавно сменил цель `db push` по умолчанию) | Версия CLI закреплена в CI; обновлять осознанно |
| Утечка служебного ключа | Низкая: ключ только в `.env.local` | Проверка истории git в OPERATIONS.md, ротация ключа |
| Ошибка в новой миграции ослабит права | Средняя при развитии | Структурный тест прав и CI на каждый pull request |
